# MIDI → CV/Gate: прошивка для платы «MIDI Analog Filter alpha»

Прошивка для прототипа **MIDI Analog Filter (PRIBORE PROTOTYPE, ALPHA)**: принимает MIDI
(DIN-разъём и USB) и превращает его в управляющие напряжения:

```
MIDI IN (DIN) ─ оптрон 6N137 ─┐
                              ├─► STM32 ─► DAC 0…3.3 В ─► ОУ ×3.06 ─► CV 0…10 В
USB (MIDI + COM-порт) ────────┘     │
                                    ├─► GATE (0/5 В, пока нажата нота)
                                    ├─► NOTEON-светодиод
                                    └─► CLOCK (тактовые импульсы из MIDI Clock)
MIDI THRU — чисто аппаратный, работает даже без прошивки.
```

Что делает по умолчанию:

| Выход | Что на нём | Откуда |
|---|---|---|
| Площадка **CV** (J1) | высота ноты, 1 В/октаву, нота C2 (36) = 0 В, + pitch bend ±2 | DAC1 (PA4) |
| **Срез фильтра** (CV_FREQ_CTRL) | MIDI CC74, 0…127 → 0…10 В, с плавным сглаживанием | DAC2 (PA5) |
| Площадка **GATE** (J14) | 5 В пока держится нота (приоритет последней ноты, педаль CC64) | PA6 |
| Площадка **CLOCK** (J31) | импульс 5 мс на каждые 6 MIDI Clock (шестнадцатые) | PB8 |
| USB | плата видна в компьютере как MIDI-устройство **«MIDI-CV Alpha»** + COM-порт для настроек | PB14/PB15 |

**Наглядные схемы подключения** (отдельно для каждого шага) — в [`docs/wiring.html`](docs/wiring.html):
открой файл в браузере. На этой плате CV, GATE и CLOCK — круглые площадки под пайку, а не гнёзда.

Всё это можно поменять: кнопкой LEARN или командами в COM-порту (см. ниже).

В плате есть свой **USB-загрузчик**: ST-Link нужен только один раз, для самой первой прошивки.
Дальше новые версии заливаются прямо по USB-кабелю (см. «Обновление прошивки по USB»).
Например, ровно то, что нарисовано на листке — «CC15 = 121 → 0…5 В на выходе» —
делается командами `src jack cc 15` и `range jack 5000`.

> ⚠️ Прошивка собрана и логика протестирована на компьютере (74 автотеста), но на
> живой плате её ещё никто не запускал. Первое включение — по шагам ниже, с мультиметром.

## Что у тебя на фото

| Штука | Зачем |
|---|---|
| Большая зелёная плата | Сам прибор. Верхняя половина — аналоговый фильтр (транзисторная лестница, L/R вход/выход). Нижняя — MIDI-часть: DIN IN/THRU, USB-B, микроконтроллер STM32, кнопка LEARN, разъёмы SWD и USART1. |
| Зелёная флешка **ST-LINK V2** | Программатор. Через него заливаем прошивку в STM32. |
| Провод с 4 «мамами» (дюпонт) | Соединить ST-Link с платой. |
| Чёрная гребёнка на 4 пина | Впаять в разъём **SWD** на плате (туда подключается ST-Link). |
| Жёлтые гребёнки | Для чёрной платки (или для разъёма USART1 на большой плате — там 3 пина). |
| Маленькая чёрная плата | Отдельная отладочная плата STM32 с micro-USB. **Для этой прошивки не нужна.** Если хочешь её тоже задействовать — скинь маркировку чипа, подскажу. |

## Пошагово: от коробки до работающего прибора

### Шаг 0. Голая плата: проверить до прошивки

На плате стоит **STM32F446RET6**, и пока он пустой. USB у этой платы разведён на ножки
PB14/PB15, а встроенный USB-загрузчик STM32 работает только на PA11/PA12. Поэтому сам по себе
пустой чип по USB с компьютером **не подружится**: первый раз прошиваем через ST-Link
(загрузчик + основную прошивку разом), и дальше плата определяется в компьютере как
MIDI-устройство + COM-порт, а обновляется по USB.

Перед прошивкой, 5 минут с мультиметром:
1. Воткни USB-B в компьютер. Компьютер пока ничего не найдёт — это нормально.
2. Между пинами 1 и 3 разъёма SWD (J13) должно быть **3.3 В**.
3. На ОУ/фильтре должны быть **+15 В и −15 В** (относительно земли). Если их нет —
   аналоговые выходы работать не будут, но прошить всё равно можно.
4. Для F446 на схеме пометка: **ножка 47 — перемычка 0 Ом на землю, а не конденсатор**
   (у F205/F405 там VCAP2). Проверь, что так и запаяно, и что на ножке 31 (VCAP1) стоит
   конденсатор 2.2 мкФ (C40). Без него ядро процессора не стартует и ST-Link не подключится.

### Шаг 1. Паяем разъём SWD

На плате, слева от микроконтроллера, есть ряд отверстий с подписью **SWD** (на схеме — J13).
Впаиваем туда чёрную 4-пиновую гребёнку в **первые 4 отверстия** (квадратная площадка — это пин 1).

Распиновка J13 (со схемы):

| Пин J13 | Сигнал |
|---|---|
| 1 (квадратный) | +3.3 В |
| 2 | SWCLK |
| 3 | GND |
| 4 | SWDIO |
| 5, 6 | не подключены |

По желанию: в разъём **USART1** (J22, 3 пина: TX, RX, GND) можно впаять кусок жёлтой гребёнки —
это запасная отладочная консоль (115200 бод), если вдруг USB не заведётся. Для неё нужен
отдельный USB-UART переходник на 3.3 В, ST-Link V2 так не умеет.

### Шаг 2. Ставим программу для прошивки

Скачай и установи **STM32CubeProgrammer** (бесплатно, Windows/macOS/Linux):
<https://www.st.com/en/development-tools/stm32cubeprog.html> (нужна регистрация на сайте ST).
Вместе с ним ставятся драйверы ST-Link. На Windows, если ST-Link не определяется, отдельно
поставь драйвер **STSW-LINK009**.

Альтернатива для Linux/macOS — консольная утилита `st-flash` (пакет `stlink-tools` / `stlink`).

### Шаг 3. Подключаем ST-Link к плате

У ST-Link V2 (зелёный алюминиевый клон) разъём 2×5, распиновка напечатана на корпусе:

```
        RST  1 ● ● 2  SWDIO   ← провод на J13 пин 4
        GND  3 ● ● 4  GND     ← провод на J13 пин 3
 прорезь SWIM 5 ● ● 6  SWCLK   ← провод на J13 пин 2
       3.3V  7 ● ● 8  3.3V
       5.0V  9 ● ● 10 5.0V
```

Все три нужных сигнала — в **одном ряду** (чётные пины 2, 4, 6), со стороны, где в стенке
разъёма **нет прорези**. Прорезь — на стороне RST/GND/SWIM. Мамы дюпонов надеваются прямо на
штырьки внутри разъёма ST-Link.

| Провод (шлейф из комплекта) | ST-Link | Сигнал | Плата, J13 |
|---|---|---|---|
| **зелёный** | **2** | SWDIO | пин 4 |
| **синий** | **4** | GND | пин 3 |
| **фиолетовый** | **6** | SWCLK | пин 2 |
| белый | 8 | 3.3V | пин 1 — **только если плата не на USB-кабеле** |

На ST-Link провода идут подряд сверху вниз (как на наклейке): зелёный на пин 2, синий на 4,
фиолетовый на 6, белый на 8. На плате порядок обратный: белый на пин 1, фиолетовый на 2,
синий на 3, зелёный на 4 — так и должно быть.

Перепутать ряды не страшно: ничего не сгорит, просто не пройдёт Connect — тогда переставь
три провода на соседний ряд. Проверить мультиметром: ST-Link воткнут в компьютер, чёрный щуп
на пин 4 — на пине 8 должно быть 3.3 В, на пине 10 — 5 В.

Питание платы — от **USB-кабеля** (разъём USB-B на плате, в компьютер). От USB питается
всё: и 3.3 В для процессора, и ±15 В для аналоговой части (там стоит повышающий DC/DC).
Поэтому 3.3 В от ST-Link не нужен — два источника на одной шине ни к чему.

Если USB-кабеля под рукой нет — надень и белый провод (ST-Link пин 8, 3.3V → плата, пин 1), тогда
ST-Link запитает только процессор (аналоговая часть работать не будет, но прошить получится).
**Только не одновременно с USB.**

### Шаг 4. Прошиваем

Готовый файл уже лежит в репозитории: **`firmware/prebuilt/midi_cv_full.hex`** — это
загрузчик и основная прошивка в одном файле. Через ST-Link это делается **один раз**.

В STM32CubeProgrammer:
1. Справа вверху выбери **ST-LINK**, порт **SWD**, нажми **Connect**.
   Внизу в логе должно появиться имя чипа — **STM32F446xC/E** (прошивка подходит и к
   F205/F405, если когда-нибудь запаяют их).
2. Слева вкладка **Erasing & Programming** (иконка со стрелкой вниз).
3. **File path** → выбери `midi_cv_full.hex`. Галочки **Verify programming** и
   **Run after programming** — включи.
4. **Start Programming**. Через пару секунд — «File download complete».
5. **Disconnect**.

То же самое из консоли:
```
st-flash --format ihex --reset write firmware/prebuilt/midi_cv_full.hex
```

#### Если STM32CubeProgrammer не ставится (или сайт ST не даёт скачать)

Прошить можно бесплатным **OpenOCD** с GitHub, без регистрации (Windows):

1. Скачай `xpack-openocd-…-win32-x64.zip` со страницы
   <https://github.com/xpack-dev-tools/openocd-xpack/releases> и распакуй, например в `C:\openocd`.
2. Положи `midi_cv_full.hex` в папку `C:\openocd\bin`.
3. Открой там командную строку (в Проводнике в адресной строке папки набери `cmd` и Enter) и выполни:
   ```
   openocd -f interface/stlink.cfg -f target/stm32f4x.cfg -c "adapter speed 480" -c "program midi_cv_full.hex verify reset exit"
   ```
4. Успех выглядит так: `** Programmed Successfully **`, `** Verified OK **`, `** Resetting Target **`.

Если пишет `Error: open failed` или `LIBUSB_ERROR_...` — Windows не дала программе доступ к ST-Link.
Скачай **Zadig** (<https://zadig.akeo.ie>), запусти, в меню Options включи *List All Devices*,
выбери в списке **STM32 STLink**, справа выбери драйвер **WinUSB** и нажми *Install / Replace Driver*.
Потом повтори шаг 3.

Если пишет `unable to connect to the target` / `init mode failed` — ST-Link работает, но не видит
плату: проверь провода и ряд на ST-Link (см. шаг 3) и что белый провод даёт 3.3 В на пин 1.

macOS: `brew install open-ocd`, Linux: `sudo apt install openocd` — команда та же.

Если **Connect** не проходит:
- проверь три провода (чаще всего перепутаны SWDIO и SWCLK);
- плата должна быть запитана (USB воткнут);
- в настройках подключения поставь **Frequency** пониже (например 480 кГц),
  **Mode: Normal**, **Reset mode: Software reset**. Пин RESET на разъём SWD не выведен,
  поэтому «Connect under reset» тут не работает.

### Шаг 5. Проверяем, что ожило

1. Вытащи и снова вставь USB. Компьютер должен найти два устройства:
   **MIDI-устройство «MIDI-CV Alpha»** и **COM-порт** (на Windows 10/11 драйверы не нужны).
   Если вместо этого светодиод NOTEON медленно мигает и появилось «MIDI-CV Alpha Updater» —
   загрузчик жив, а основной прошивки нет: залей её по USB (см. «Обновление прошивки по USB»)
   или проверь, что через ST-Link шился именно `midi_cv_full.hex`.
2. Открой COM-порт любым терминалом: PuTTY / Tera Term (Windows), `screen /dev/ttyACM0`
   (Linux), `screen /dev/tty.usbmodem*` (macOS). Скорость любая. Появится приглашение `>`.
3. Набери `status` + Enter. Должно показать чип, частоту кварца, настройки.
   Строка `clock: crystal 8 MHz` (или другая частота) — значит, кварц нашёлся и USB будет
   работать стабильно. Частоту кварца прошивка определяет сама.
4. Мультиметр на площадку **CV** (J1), минус — на землю (пин 3 разъёма SWD):
   - `set jack 0` → ~0 В
   - `set jack 5000` → ~5 В
   - `set jack 10000` → ~10 В
   - `set jack off` → вернуть выход прошивке
5. GATE: `gate on` → ~5 В на площадке GATE (J14), `gate off` → ~0 В.
   Если наоборот — `gateinv on` и `save`.
6. Подключи MIDI-клавиатуру в **MIDI IN** (или играй из DAW через USB): при нажатой клавише
   горит светодиод **NOTEON**, на CV — напряжение ноты (C2 = 0 В, C3 = 1 В, C4 = 2 В…),
   на GATE — 5 В. Крути контроллер CC74 (часто это ручка «Cutoff»/«Brightness») — должен
   меняться срез фильтра.

### Шаг 6. Калибровка (чтобы ноты строили)

У DAC и резисторов есть разброс, поэтому 1 В/октаву «из коробки» будет неточным
на несколько процентов. Калибровка по двум точкам, нужен мультиметр:

```
> set jack 1000        ← измерь напряжение на CV, например получилось 1.012 В
> set jack 8000        ← измерь, например 8.061 В
> cal jack 1012 8061   ← вписываем намеренное в милливольтах
> set jack 1000        ← проверяем: теперь должно быть ровно 1.000
> set jack 8000        ← и 8.000
> set jack off
> save
```

Так же можно откалибровать выход фильтра (`filter` вместо `jack`), но там это обычно не нужно.

## Как пользоваться

### Кнопка LEARN

| Действие | Что происходит | Светодиод NOTEON |
|---|---|---|
| Короткое нажатие | Обучение CC для **фильтра**: покрути любую ручку на клавиатуре — фильтр будет слушать её | быстро мигает |
| Ещё одно короткое нажатие (во время обучения) | То же, но для выхода **CV** (вместо высоты ноты на нём будет эта ручка) | двойные вспышки |
| Третье короткое нажатие | Отмена | — |
| Держать **3 секунды** | Обучение **MIDI-канала**: нажми ноту на клавиатуре — прибор будет слушать только её канал | медленно мигает |
| Держать **8 секунд** | Сброс на **Omni** (слушать все каналы) | 3 вспышки |
| Держать **15 секунд** | Сброс **всех настроек** на заводские (и сохранение) | 3 вспышки |
| Держать, **втыкая USB** | Режим обновления прошивки (см. ниже) | медленно мигает, пока не отпустишь и дальше |

Обучение само отменяется через 10 секунд. Всё выученное сразу сохраняется во флеш.

### Команды в COM-порту

| Команда | Что делает |
|---|---|
| `help` | список команд |
| `status` | всё текущее состояние |
| `ch 1`…`ch 16`, `ch omni` | MIDI-канал |
| `src jack pitch` | на выходе CV (J1) — высота ноты (по умолчанию) |
| `src jack vel` | …velocity последней ноты |
| `src jack cc 15` | …контроллер CC15 |
| `src jack at` / `src jack bend` | …aftertouch / pitch bend |
| `src filter cc 74` | что управляет фильтром (те же варианты) |
| `range jack 5000` | напряжение при значении 127 (для CC/velocity), в мВ: 5000 = 0…5 В |
| `smooth filter 5` | сглаживание ступенек CC, мс (0 = выкл) |
| `zero 36` | какая нота даёт 0 В на pitch-выходе |
| `bend 2` | диапазон pitch bend в полутонах |
| `retrig on/off` | короткий провал GATE при легато (для перезапуска огибающей) |
| `clockdiv 6` | сколько MIDI Clock на один импульс CLOCK (24 = четверти, 6 = шестнадцатые) |
| `set jack 5000` / `set jack off` | вручную выставить напряжение (тест) |
| `gate on/off` | вручную GATE (тест) |
| `cal jack <мВ@1В> <мВ@8В>` | калибровка (см. шаг 6) |
| `learn filter/jack/ch` | то же, что кнопка |
| `save` | сохранить настройки во флеш |
| `defaults` | заводские настройки (потом `save`) |
| `panic` | отпустить все ноты |
| `dfu` | перезапуститься в режим обновления прошивки |

Изменения командами применяются сразу, но **сохраняются только после `save`**.

### Ещё

- Всё, что приходит в **DIN MIDI IN**, пересылается в компьютер по USB — плата работает
  ещё и как MIDI-интерфейс.
- То, что компьютер шлёт по USB MIDI, уходит на USART2_TX (тестпоинт J19) — задел под
  будущий MIDI OUT, разъёма на этой плате нет.
- MIDI THRU — аппаратный, прошивка в нём не участвует.

## Обновление прошивки по USB

ST-Link больше не нужен. Нужна утилита **dfu-util** (бесплатная):
- **Windows**: скачай архив `dfu-util-0.11-binaries.tar.xz` с
  <https://dfu-util.sourceforge.net/releases/>, распакуй, `dfu-util.exe` лежит в `win64`.
  Драйвер ставить не надо — плата сама говорит Windows, что ей нужен WinUSB.
- **macOS**: `brew install dfu-util`
- **Linux**: `sudo apt install dfu-util` (запускать через `sudo` или поставить
  `firmware/tools/50-midi-cv.rules` в `/etc/udev/rules.d/`).

Как обновить:
1. Переведи плату в режим обновления — любым способом:
   - **держи LEARN и воткни USB** (потом отпусти), или
   - в COM-порту набери `dfu`.

   Светодиод NOTEON медленно мигает, в компьютере появилось устройство
   **«MIDI-CV Alpha Updater»** (MIDI и COM-порт в этом режиме пропадают — так и надо).
2. Запусти:
   ```
   dfu-util -a 0 -D midi_cv_alpha.dfu
   ```
   Свежий файл — `firmware/prebuilt/midi_cv_alpha.dfu`. Во время записи светодиод мигает
   быстро. В конце будет `Download done.` / `state(2) = dfuIDLE`.
3. Через полторы секунды плата сама перезапустится уже с новой прошивкой.

Если передумал — короткое нажатие LEARN выводит из режима обновления без прошивки.

**Окирпичить не получится.** Начало прошивки (вектор сброса) записывается последним, когда
весь файл уже принят и проверен. Если выдернуть кабель посередине, загрузчик при следующем
включении увидит, что прошивки нет, и сам останется в режиме обновления — просто запусти
`dfu-util` ещё раз. Чужой файл (например, `midi_cv_full.hex`, переделанный в bin, или прошивка
от другого устройства) загрузчик отвергнет. А сам загрузчик через USB перезаписать нельзя —
только ST-Link'ом, так что он всегда остаётся живым.

## Сборка из исходников (если захочешь что-то поменять)

Нужен `arm-none-eabi-gcc` и `make`. Проще всего на Linux или в WSL на Windows:

```
sudo apt install gcc-arm-none-eabi libnewlib-arm-none-eabi make
cd firmware
make          # → build/: midi_cv_alpha.dfu (для USB), midi_cv_full.hex (для ST-Link)
make test     # прогнать тесты на компьютере (MIDI-логика и загрузчик)
make dfu      # обновить плату по USB (dfu-util)
make flash    # прошить всё через ST-Link (st-flash)
make release  # обновить файлы в firmware/prebuilt/
```

Все библиотеки (TinyUSB для USB, заголовки CMSIS от ARM/ST) уже лежат в `firmware/lib/`,
ничего докачивать не надо.

Где что лежит:

| Файл | Что внутри |
|---|---|
| `firmware/src/engine.c` | вся MIDI-логика: стек нот, gate, CC→CV, LEARN, clock |
| `firmware/src/midi_parser.c` | разбор MIDI-потока (running status, realtime, SysEx) |
| `firmware/src/board.c` | железо основной прошивки: GPIO, DAC, UART, хранение настроек |
| `firmware/src/console.c` | команды COM-порта |
| `firmware/src/settings.c` | настройки и их хранение во флеше (с CRC) |
| `firmware/bootloader/` | USB-загрузчик (DFU): `main.c` — режимы и USB, `dfu_image.c` — запись прошивки |
| `firmware/common/` | общее для обоих: тактирование с автоопределением кварца, флеш, USB, карта памяти |
| `firmware/tests/` | тесты MIDI-логики и загрузчика, запускаются на ПК |
| `docs/HARDWARE.md` | распиновка платы по схеме, расчёты, замечания к схеме |

## Что дальше

В папке с заданием лежит ТЗ **MIDI-CV/Gate rev 1.1** — это уже следующее устройство
(внешний 16-битный DAC80502, STM32F446RET6, EEPROM, 4 gate-выхода, транспорт, SysEx).
Эта прошивка — рабочая основа под него: парсер MIDI, стек нот с Last Note Priority,
педаль, pitch bend, LEARN с теми же таймингами (3 с / 10 с), сглаживание AUX CV,
merge DIN+USB уже сделаны так, как описано в ТЗ. Чего пока нет (потому что на alpha-плате
нет такого железа): DAC80502 по SPI, EEPROM 24C512, GATE1…4, Start/Stop/Continue/Run/Reset,
SysEx-конфигурация, портаменто. Подробнее — в `docs/HARDWARE.md`.
